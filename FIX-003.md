# FIX-003 — Strongly typed pluggable config via `ports.PluginConfig`

> Carved out of `ARCH_LINT_PLAN.md` § F-003 / ARCH-003 as a sibling
> runbook to FIX-004 (domain split) and the shipped FIX-006 (adapter
> ACL refactor). This file owns the executable plan; ARCH_LINT_PLAN
> retains only the policy framing and points here.

## Why this exists

Every plugin attachment point in the bridge currently surfaces an
opaque `Options map[string]any` blob:

| File | Type | Field |
|---|---|---|
| `ports/blueprint.go` | `StoreConfig` | `Options map[string]any` |
| `ports/blueprint.go` | `SessionDef` | `Options map[string]any` |
| `ports/blueprint.go` | `ReceiverDef` | `Options map[string]any` |
| `ports/blueprint.go` | `SubscriptionDef` | `Options map[string]any` |
| `ports/blueprint.go` | `SenderDef` | `Options map[string]any` |
| `ports/blueprint.go` | `BindingDef` | `Options map[string]any` |
| `ports/stores.go` | `StoreSpec` | `Options map[string]any` |
| `domain/route.go` | `DestinationBinding` | `Options map[string]any` |
| `domain/route.go` | `SubscriptionPlan` | `Options map[string]any` |
| `domain/route.go` | `PublisherPlan` | `Options map[string]any` |

`domain/route.go:DispatchPlan.Headers` is a different concept (runtime
message headers, not config) and is **out of scope** for this plan.

Consequences of the current shape:

- Misspelled keys, missing required fields, and type errors fail at
  runtime, not at parse time.
- The lint analyzer planned for F-003 has no anchor type to enforce
  against — there is nothing in `ports/` that says "this is a plugin
  config, here is its contract".
- Each adapter factory re-implements its own `mapstructure.Decode` +
  validation, leading to inconsistent error wording and partial
  validation coverage.
- The escape hatch becomes load-bearing: anyone may stuff anything
  into the map, and the bridge cannot reject it before assembly.

## Constraint

No backward compatibility. No `Options map[string]any` fallback, no
`OptionsLegacy` shim, no dual-decoded struct. Once this lands, every
plugin attachment point holds a typed `ports.PluginConfig` and the
two-stage parser is the only path that fills it.

## Target shape

### The marker interface (in `ports/`)

```go
package ports

// PluginConfig is the marker interface every plugin (transport,
// store, processor, credential source, etc.) implements with its
// own concrete config struct. Implementations are typically a
// plain Go struct with yaml/json tags and a Validate() method that
// runs before the bridge assembles any runtime component.
type PluginConfig interface {
    // Kind returns the discriminator used in the blueprint and the
    // registry key under which the decoder is registered. It must
    // match the value the user writes under `transport:` /
    // `type:` in the blueprint.
    Kind() string

    // Validate checks the config for completeness and
    // consistency. Validate must be a pure function: no I/O, no
    // network, no goroutines. It runs once during config parsing.
    Validate() error
}
```

### Per-adapter typed config (in the adapter package)

```go
// adapters/aws/transport/sqs/config.go
package sqs

type Config struct {
    QueueURL          string        `yaml:"queue_url"        json:"queue_url"`
    Region            string        `yaml:"region"           json:"region"`
    VisibilityTimeout time.Duration `yaml:"visibility"       json:"visibility"`
    MaxMessages       int           `yaml:"max_messages"     json:"max_messages"`
}

func (c Config) Kind() string { return "aws.sqs" }

func (c Config) Validate() error {
    if c.QueueURL == "" {
        return errors.New("sqs: queue_url required")
    }
    if c.MaxMessages < 1 || c.MaxMessages > 10 {
        return errors.New("sqs: max_messages must be 1..10")
    }
    return nil
}
```

### The registry (in `ports/`)

```go
package ports

// RawConfig is an opaque carrier for not-yet-decoded plugin options.
// It is produced by the config-source adapter (yaml/json/etc.) and
// consumed by exactly one plugin decoder. It MUST NOT cross any
// other boundary.
type RawConfig interface {
    // Decode populates target from the raw bytes. Implementations
    // typically delegate to mapstructure or yaml.Unmarshal.
    Decode(target any) error
}

type ConfigDecoder func(raw RawConfig) (PluginConfig, error)

type Registry struct {
    mu       sync.RWMutex
    decoders map[string]ConfigDecoder
}

func (r *Registry) Register(kind string, dec ConfigDecoder) {
    r.mu.Lock()
    defer r.mu.Unlock()
    if _, dup := r.decoders[kind]; dup {
        panic("ports: duplicate plugin kind " + kind)
    }
    r.decoders[kind] = dec
}

func (r *Registry) Decode(kind string, raw RawConfig) (PluginConfig, error) {
    r.mu.RLock()
    dec, ok := r.decoders[kind]
    r.mu.RUnlock()
    if !ok {
        return nil, fmt.Errorf("unknown plugin kind %q", kind)
    }
    return dec(raw)
}
```

`RawConfig` is interface-only inside `ports/`. Its concrete
implementation (the one that actually wraps `[]byte` or
`map[string]any` and calls `mapstructure`) lives in `config/` so
`encoding/json` and `mapstructure` stay out of `ports/`.

### Adapter self-registration

```go
// adapters/aws/transport/sqs/register.go
package sqs

import "github.com/mariotoffia/gobridge/ports"

func init() {
    ports.DefaultRegistry.Register("aws.sqs",
        func(raw ports.RawConfig) (ports.PluginConfig, error) {
            var c Config
            if err := raw.Decode(&c); err != nil { return nil, err }
            if err := c.Validate(); err != nil { return nil, err }
            return c, nil
        })
}
```

The composition root imports the adapters it wants
(`_ "…/adapters/aws/transport/sqs"`); the registry is populated by
the import graph. Unimported adapters never reach the binary.

### Updated blueprint shape

```go
type SenderDef struct {
    ID        string             `yaml:"id"          json:"id"`
    Transport string             `yaml:"transport"   json:"transport"` // discriminator
    SessionID string             `yaml:"session_id,omitempty" json:"session_id,omitempty"`
    Config    ports.PluginConfig `yaml:"-"           json:"-"`         // populated by the parser
}
```

Same shape applies to `SessionDef`, `ReceiverDef`, `SubscriptionDef`,
`BindingDef`, and `StoreConfig`. The blueprint type now holds a
typed `PluginConfig`. `cfgshape` can require it.

### Two-stage parsing in `config/`

```go
// config/parse.go
func Parse(src []byte, reg *ports.Registry) (*ports.BridgeConfig, error) {
    // Stage 1 — decode the *frame*: IDs, transport discriminators,
    // and a deferred RawConfig per plugin attachment point.
    var frame frame // package-private intermediate type
    if err := yaml.Unmarshal(src, &frame); err != nil { return nil, err }

    bc := &ports.BridgeConfig{ /* copy non-plugin fields */ }

    // Stage 2 — for each plugin attachment point, dispatch to the
    // registry to get a typed PluginConfig.
    for _, sd := range frame.Senders {
        cfg, err := reg.Decode(sd.Transport, sd.rawOptions)
        if err != nil {
            return nil, fmt.Errorf("sender %s: %w", sd.ID, err)
        }
        bc.Senders = append(bc.Senders, ports.SenderDef{
            ID: sd.ID, Transport: sd.Transport,
            SessionID: sd.SessionID, Config: cfg,
        })
    }
    // ... same for receivers, sessions, stores, bindings, subscriptions
    return bc, nil
}
```

Stage 1 is the format-aware part (`yaml`/`json`/`mapstructure`).
Stage 2 is type-aware. The parser never lets `map[string]any` cross
into `ports/`.

### Generic factory at the runtime boundary

```go
// ports/factory.go
type Factory[C PluginConfig, P any] func(context.Context, C) (P, error)
```

The runtime calls `factory(ctx, cfg.(sqs.Config))` exactly once, at
composition. Adapters receive their own concrete type, no reflection,
no map lookups.

## Phased migration

Each phase ends with `make lint && make test` green before commit.
A failing intermediate state blocks subsequent phases because
`goimports` will have stale paths to fix.

### Phase 0 — Land the interface and registry (no adapter changes) - DONE

1. Add `ports/plugin_config.go` with `PluginConfig`, `RawConfig`,
   `Registry`, `DefaultRegistry`, `Factory[C,P]`.
2. Add `config/raw_config.go` with the concrete `RawConfig`
   implementation (wraps `map[string]any` from yaml stage 1).
3. No call-site changes yet. Existing code keeps working.
4. `make lint && make test`.
5. Commit: `FIX-003 phase 0: introduce ports.PluginConfig and registry`.

### Phase 1 — Migrate `ports/blueprint.go` plugin attachment points - DONE

**Status:** Resolved 2026-05-05. The six plugin attachment points in
`ports/blueprint.go` (`StoreConfig`, `SessionDef`, `ReceiverDef`,
`SubscriptionDef`, `SenderDef`, `BindingDef`) now expose a typed
`Config ports.PluginConfig` with an unexported `raw ports.RawConfig`
accessed only via `Raw()` / `SetDecoded()`. `config/parse.go` performs
two-stage decoding: stage 1 mirrors YAML into raw payloads; stage 2
walks the blueprint, resolves the discriminator (`Type` for stores,
`Transport` for sessions/receivers/senders, inherited for subscriptions
and bindings), and routes through `ports.Registry`. Errors wrap with
`config: <attachment> %q (kind %q): %w`. New
`ParseWithRegistry` / `ParseFileWithRegistry` siblings expose a
registry seam; `Parse` / `ParseFile` delegate to
`ports.DefaultRegistry`. `validateStaleClaimDuration` and existing
test files were migrated to the typed surface; new
`parse_phase1_test.go` covers unknown / missing kind, validation
failure, success on every attachment point, sender-not-found for
bindings, and the empty-options-still-consults-registry path. Build,
`gofmt`, `go vet`, and `go test` are green for `./ports/...` and
`./config/...`. Whole-repo `make test/lint` remains failing by design
— that is the Phase 2 forcing function called out in step 3.

1. For each of `StoreConfig`, `SessionDef`, `ReceiverDef`,
   `SubscriptionDef`, `SenderDef`, `BindingDef`: replace
   `Options map[string]any` with `Config ports.PluginConfig` and a
   private `raw ports.RawConfig` for the parser to fill.
2. Update `config/parse.go` to do two-stage decoding for every plugin
   attachment point. Errors must include the user-facing ID and
   the `Kind()` value.
3. Build will fail across every adapter — that is the intended
   forcing function for Phase 2.
4. Per-attachment-point unit tests for the parser: unknown `Kind`,
   missing `Kind`, validation failure, success path.
5. Acceptance: `ports/blueprint.go` has zero `map[string]any` fields.

### Phase 2 — Migrate adapters one family at a time - DONE

For each adapter family (transport, store, credentials, processor):

1. Add `Config` struct with yaml/json tags, `Kind()`, `Validate()`.
2. Add `register.go` with the `init()` registration.
3. Update the adapter factory signature from
   `New(spec map[string]any)` to `New(cfg ThisAdapter.Config)`.
4. Delete the now-dead `mapstructure.Decode` call inside the factory.
5. Update adapter tests to construct `Config{}` directly.
6. `make lint && make test`.
7. Commit per family: `FIX-003 phase 2.<family>: migrate <family> to PluginConfig`.

Adapter families, in suggested order (smallest blast radius first):

- `adapters/native/credentials/file` (single config struct, isolated)
- `adapters/aws/credentials/ssm`
- `adapters/aws/config/dynamodb`
- `adapters/native/store/sqliteoutbox` and `sqlitedlq`
- `adapters/aws/store/dynamodboutbox` and `dynamodbdlq`
- `adapters/aws/transport/sqs`
- `adapters/azure/transport/servicebus`
- `adapters/amqp/transport/amqp091` and `amqp10`
- `adapters/mqtt/transport/paho`
- `adapters/http/transport`

### Phase 3 — Migrate `domain/route.go` runtime carriers - DONE

**Status:** Resolved 2026-05-05. `domain.DestinationBinding`,
`SubscriptionPlan`, and `PublisherPlan` lost their `Options
map[string]any` fields; `DestinationBinding` gained a typed
`Headers map[string]any` carve-out for static dispatch headers
(populated only in tests today; threading from
`ports.BindingDef.Headers` is a tracked follow-up). `ports.StoreSpec`
was deleted; `ports.StoreFactory` now takes
`cfg ports.PluginConfig` directly, with an additional
`runtime ports.OutboxRuntimeOptions` channel on `NewOutboxStore` so
runtime-derived knobs (`StaleClaimDuration`) travel separately from
user-supplied plugin config. New typed configs landed for the
native stores (`MemoryConfig`, `SQLiteConfig`) and the AWS DynamoDB
store (`DynamoDBConfig`), each registered via `init()`. The bridge
builder's `outboxRuntimeOptions` honours an explicit
`stale_claim_duration` override read from `StoreConfig.Raw()` and
otherwise derives the value from the routes' `StepDownGrace`
policy. `domain/` retains `_no_external_deps_`. `make lint` and
`make test` are green across every module.

1. `DestinationBinding.Options`, `SubscriptionPlan.Options`,
   `PublisherPlan.Options` become `Config ports.PluginConfig`.
2. `ports/stores.go:StoreSpec.Options` becomes
   `Config ports.PluginConfig`. The `StoreFactory` interface methods
   take the typed config:
   ```go
   NewLeaseStore(ctx context.Context, cfg ports.PluginConfig) (LeaseStore, error)
   ```
   Implementations type-assert to their concrete `Config`.
3. Bridge builder updates: instead of constructing maps, it threads
   the already-decoded `PluginConfig` through to the runtime types.
4. `make lint && make test`.

### Phase 4 — Land `cfgshape` analyzer

1. Build `scripts/cfgshape/` mirroring `scripts/aclcheck/`.
2. Rules:
   - In `ports/` and `domain/`: any exported field, function
     parameter, or return type matching `map[string]any`,
     `map[string]interface{}`, `json.RawMessage`, `*structpb.Struct`,
     or unbounded `[]byte` named `Config`/`Options`/`Settings`/
     `Extra`/`Raw` is a violation. Exempt `*_test.go`.
   - In `adapters/<vendor>/<category>/<impl>/`: the package MUST
     export at least one type that satisfies
     `ports.PluginConfig` (verified via `types.Implements`). The
     package MUST contain a `register.go` that calls
     `ports.DefaultRegistry.Register`. Exempt `acl/` sub-directories
     and pure-test packages.
   - The `Validate()` method MUST have a non-empty body
     (`*ast.BlockStmt.List > 0`) and at least one `*_test.go` file
     in the same package must reference it.
3. Wire into `make lint`:
   ```makefile
   build-cfgshape:
       @cd scripts/cfgshape && go build -o $(PWD)/bin/cfgshape ./...

   lint-cfgshape: build-cfgshape ## Enforce typed pluggable config shapes
       @bash -c 'set -eo pipefail; for modfile in $$(find . -name go.mod -not -path "*/vendor/*" | sort); do \
         dir=$$(dirname $$modfile); \
         (cd "$$dir" && go vet -vettool=$(PWD)/bin/cfgshape ./...) ; \
       done'

   lint: lint-arch-check lint-gofmt lint-go-vet lint-go lint-aggregate lint-acl lint-cfgshape
   ```
4. `make lint && make test`.

### Phase 5 — Tighten arch lint vendor admission

1. Add `encoding/json`, `gopkg.in/yaml.v3`,
   `github.com/go-viper/mapstructure/v2` as named vendors in
   `.go-arch-lint.yml`.
2. Deny them from `domain` and `ports` (they are inner-ring,
   format-neutral). All other components (`config`, `runtime`,
   `bridge`, `httpapi`, adapters, processors, deployment) keep
   them — they have legitimate wire-format and payload-parsing uses.
3. `make lint && make test`.

### Phase 6 — Mapping regression sentinels

Extend `scripts/lint-arch-mapping-test.sh` with one
`assert_pkg_in_component` line per adapter package, asserting it
maps to its expected adapter component. A new adapter added without
a typed config and a registration call fails the regression.

### Phase 7 — Documentation

1. Add an AsciiDoc page under `docs/` describing
   the `PluginConfig` contract, the registry, and how to add a new
   plugin (write `Config`, `Kind`, `Validate`, `register.go`).
2. Update `ARCHITECTURE.md` to reference the typed-plugin-config
   architecture.
3. Update `ARCH_LINT_PLAN.md` F-003 status to "Closed via FIX-003"
   once `cfgshape` is enforcing.

## Cost estimate

Realistic effort: **3–4 dedicated days** of focused work.

- Phase 0 (interface + registry): half a day.
- Phase 1 (blueprint migration + parser rewrite): full day. This is
  the highest-fan-out step; every adapter test fails until Phase 2.
- Phase 2 (adapters): one to one-and-a-half days, parallelizable
  across adapter families if more than one engineer is available.
- Phase 3 (`domain/route.go` + `StoreSpec`): half a day.
- Phase 4 (`cfgshape` analyzer): half a day; mostly mirroring
  existing aclcheck/aggcheck wiring.
- Phases 5–7 (lint policy, sentinels, docs): half a day.

## Risks and how to mitigate

- **Big-bang Phase 1 break.** Adapters break the build until each is
  migrated in Phase 2. Mitigate by branching `fix-003`, working
  Phase 1 + Phase 2 in the same PR, and running `make build` after
  every adapter family. Keep PR scope to the runbook; do not bundle
  unrelated changes.
- **Adapter `init()` ordering.** Registry is populated by import
  side effects; blueprint parsing must happen *after* all adapter
  packages have been imported. The composition root already
  imports adapters explicitly — that's the trigger. Tests that
  parse a blueprint must also import the adapters they use; encode
  this in a test helper.
- **Registry duplicate-kind panic.** Two adapters claiming the same
  `Kind()` panic on `init()`. Add a unit test that imports every
  shipped adapter and asserts no panics — this catches naming
  collisions at CI time, not at user runtime.
- **Sentinel mapping drift.** The mapping regression must list
  every adapter; otherwise a new adapter slips past Phase 6.
  Mitigate: add a meta-test that walks `adapters/**` and asserts
  each leaf package is named in the regression script.
- **Validation purity.** `Validate()` must be a pure function. A
  `lint-cfgshape` advisory rule that flags `Validate()` bodies
  importing `net`, `os`, `database/sql` is cheap and prevents
  side-effectful validators.

## Acceptance

- `ports/blueprint.go`, `ports/stores.go`, `domain/route.go` contain
  zero `map[string]any` plugin-config fields.
- Every adapter package exports a type satisfying
  `ports.PluginConfig` with a non-empty `Validate()` exercised by
  tests.
- `bin/cfgshape` is built and `make lint` runs `lint-cfgshape`
  without findings.
- A trial violation (deliberately adding `Options map[string]any`
  to a `ports/*Def`) fails `make lint`.
- A new adapter family added without `register.go` fails
  `make lint` (cfgshape Phase 4 rule).
- The mapping regression names every adapter; removing one fails
  the regression.
- `make check` green at every commit boundary.

## When NOT to start

- When there are unmerged feature branches that touch
  `ports/blueprint.go`, `config/parse.go`, or any adapter factory.
  Phase 1 will conflict with every one of them. Coordinate the
  freeze.
- When there is no agreement on the discriminator format
  (`aws.sqs` vs `sqs.aws` vs `aws/sqs`). Settle the naming convention
  before writing `Kind()` returns; renaming later means rewriting
  every blueprint file in every deployment.
