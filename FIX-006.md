# FIX-006 — Refactor adapters into ACL files (promote `lint-acl` to enforcing)

> Carved out of `FINAL_DDD_HEX_CLEAN_FIX_PLAN.md` for a dedicated
> session. The `aclcheck` analyzer was built and wired up in commit
> `794f659` (FIX-006 phase 1) but runs as **advisory** because no
> existing adapter follows the `acl_*.go` naming convention. This
> document is the runbook for the per-adapter restructure that
> promotes `lint-acl` to a `make lint` gate.

## Why this exists

In Hexagonal Architecture, the Anti-Corruption Layer (ACL) is the
seam where an external SDK's vocabulary (its types, errors,
encodings) is translated into the project's domain types. Today this
translation is scattered across multiple files inside each adapter
(`receiver.go`, `headers.go`, `errors.go`, …) — future maintainers
cannot find the SDK boundary at a glance, and SDK types can leak
across the adapter without anyone noticing during review.

The DDD remedy: concentrate the SDK boundary in explicitly-named
files (`acl_*.go` or under an `acl/` sub-directory). Reviewers find
the seam in seconds; the `aclcheck` analyzer mechanically catches any
file that imports an SDK without being part of the ACL.

## Target structure (per adapter)

The convention enforced by `aclcheck`:

- A file whose name starts with `acl` (e.g. `acl.go`,
  `acl_envelope.go`, `acl_inbound.go`) is part of the ACL — it MAY
  import the vendor SDK.
- A file in an `acl/` sub-directory of the adapter package is part of
  the ACL — it MAY import the vendor SDK.
- Everywhere else inside the adapter package, the SDK import is
  forbidden.

### Recommended per-adapter split (transport adapters)

```
adapters/<vendor>/transport/<tech>/
├── acl_inbound.go    # SDK message → domain.Envelope (parses headers,
│                     # extracts trace context, maps SDK error codes)
├── acl_outbound.go   # domain.Envelope → SDK send call (formats headers,
│                     # serialises payload, applies SDK-specific options)
├── acl_errors.go     # SDK error type → domain.BridgeError classification
├── acl_session.go    # (optional) SDK Session/Connection lifecycle if it
│                     # exposes SDK types in its API
├── receiver.go       # ports.Receiver implementation, no SDK imports —
│                     # delegates to acl_inbound for translation
├── sender.go         # ports.Sender implementation, no SDK imports —
│                     # delegates to acl_outbound
├── factory.go        # ports.TransportFactory wiring, no SDK imports
└── config.go         # option DTOs, no SDK imports
```

The pattern works for non-transport adapters too:
- **stores**: `acl_query.go` (SQL/DDB query construction), `acl_row.go`
  (row → domain mapping), `store.go` (port implementation).
- **credentials**: `acl_secret.go` (SDK GetSecretValue → domain.Credential),
  `repository.go` (port implementation).
- **metrics/tracing**: `acl_emit.go` (domain metric → SDK call),
  `exporter.go` (port implementation).

### When the split doesn't fit

Some types are inherently the SDK's, not the domain's. AMQP091's
`*amqp.Channel` is the SDK's resource; the receiver loop must hold
it for the lifetime of a subscription. Two options:

1. **Wrap it.** Put `*amqp.Channel` behind an unexported `channel`
   alias in `acl_session.go`; the receiver holds the alias. The SDK
   import stays in the ACL file, the receiver doesn't import the SDK.
2. **Accept the analyzer hit.** Add a per-file exemption in the
   analyzer's `vendorPatterns` for cases where wrapping adds no
   architectural value (purely lifecycle, no translation).

Prefer (1). Don't undermine the analyzer for convenience.

## Step-by-step approach

### Phase 0 — Preparation

1. Confirm baseline: `make check` is green at HEAD; `make lint-acl`
   produces `reports/aclcheck.log` with ~113 advisory hits.
2. Pick the adapter to start with. Recommended order (smallest →
   largest):
   1. `adapters/native/store/sqlite{outbox,dlq}` (~3 violations each;
      good practice run)
   2. `adapters/aws/credentials/ssm` (7 violations, contained scope)
   3. `adapters/aws/config/dynamodb` (7 violations)
   4. `adapters/amqp/transport/amqp091` and `amqp10` (7 each)
   5. `adapters/azure/transport/servicebus` (8)
   6. `adapters/aws/metrics/cloudwatch` (9)
   7. `adapters/mqtt/transport/paho` (11)
   8. `adapters/aws/transport/sqs` (18 — biggest, save for last)
   9. `adapters/otel/{metrics,tracing}` (variable)
3. Per-adapter, the work is mechanical but not automatable. Each
   adapter ships as one commit.

### Phase 1 — Per-adapter refactor (template)

For each adapter, repeat:

1. **Identify the SDK boundary points.** `grep` the adapter for the
   SDK import; for each file that imports it, decide:
   - Does this file translate SDK types ↔ domain types? → it IS the
     ACL; rename to `acl_*.go`.
   - Does this file just hold SDK resources internally? → wrap them
     in unexported types in `acl_session.go` or similar; remove the
     SDK import from the rest of the file.
   - Does this file expose SDK types in its public API? → that's a
     leak; redesign to use domain types.

2. **Move/rename files.** Use `git mv receiver.go acl_receiver.go`
   only when the file is genuinely an ACL. Most often, the file
   stays put and SDK uses move into a new `acl_*.go` sibling.

3. **Update unit tests.** Tests inside the adapter package need no
   change (tests are exempted by the analyzer). Tests in other
   packages that import adapter internals need API updates only if
   the public API changed.

4. **Verify.**
   ```bash
   cd adapters/<vendor>/transport/<tech>
   go build ./...
   go vet ./...
   go test -race -timeout 60s ./...
   cd -
   make lint-acl   # this adapter should now show 0 violations
   ```

5. **Commit.** Format: `FIX-006: refactor <adapter> into ACL files`.

### Phase 2 — Promote `lint-acl` to enforcing

Once `reports/aclcheck.log` is empty:

1. Edit the Makefile:
   ```make
   # OLD: lint-acl writes a report and ignores exit codes
   # NEW: lint-acl runs go vet directly and fails on any violation
   lint-acl: build-aclcheck
       @bash -c 'set -e; for modfile in $$(find ./adapters -name go.mod ...); do
           dir=$$(dirname "$$modfile"); ...
           (cd "$$dir" && go vet -vettool=$(PWD)/bin/aclcheck ./...);
       done'
   ```
2. Add `lint-acl` to `lint`:
   ```make
   lint: lint-arch-check lint-gofmt lint-go-vet lint-go lint-aggregate lint-acl
   ```
3. Update `.claude/CLAUDE.md` "What each tool catches" table: mark
   `aclcheck` as **enforcing**.
4. Final `make check` must pass.

## Cost estimate

Realistic effort per adapter:

| Adapter category | Files affected | Effort |
|---|---|---|
| Native stores (sqlite outbox/dlq) | 1–3 | 30 min each |
| Credential / config adapters | 3–5 | 1 hour each |
| Transport adapters (small: amqp, sqs, mqtt) | 5–10 | 2–4 hours each |
| OTel metrics/tracing | 3–5 | 1 hour each |

Total: **~2–3 dedicated days** for the full sweep. Each adapter is
independent; you can start small to build confidence, then tackle
the larger transport adapters with the pattern firm in mind.

## Risks and how to mitigate

- **SDK type leaks into domain.** Easy to spot during the refactor:
  if a domain type has an SDK type as a field or method parameter,
  you have a deeper problem than naming. Stop and redesign.
- **Tests construct SDK types for mocks.** Tests are exempted by
  the analyzer; you don't need to refactor them. But check that any
  test helper that exposes SDK types to other test files is itself
  in an `acl_*.go` (or test) file.
- **The `acl_session.go` wrapper pattern.** Keep these wrappers
  package-private (lowercase). Exposing them re-creates the leak.
- **Analyzer false positives.** If a file legitimately imports a
  vendor that is *not* an SDK boundary (e.g., a shared utility),
  add it to a per-file allowlist in the analyzer or move it to the
  generic vendor list — but document the decision.

## Acceptance

- `reports/aclcheck.log` is empty after every adapter is refactored.
- `make lint-acl` is part of `make lint` and exits non-zero when an
  SDK import appears in a non-ACL file.
- A trial violation (drop a vendor SDK import into a non-ACL file)
  fails the check with a clear message.
- A new transport adapter scaffolded against this convention from
  day one (template: `adapters/native/store/sqliteoutbox` after
  refactor) builds without aclcheck issues.

## When NOT to start

- When you have unmerged feature branches that touch the targeted
  adapter. The file-rename will conflict with every one. Coordinate
  the freeze per adapter.
- When you don't have time to finish the chosen adapter. Half-done
  ACL refactors leave dead `acl_*.go` stubs that confuse reviewers.
