## Overview
This file is the canonical production-readiness ledger for the audited target. It merges the prior adversarial audit, the later independent source reviews, and the 2026-08-18 re-verification of every finding against HEAD plus a second adversarial pass over the MQTT adapter and core runtime. Each finding appears once with evidence, production consequence, required remediation, and a dated **Status** line. IDs are stable: closed and withdrawn findings keep their ID and status; new findings continue the numeric series (HIGH-14…, MEDIUM-18…, LOW-20…).
GoBridge is not production-ready for the complete MQTT, clustered high availability (HA), and live-reconfiguration feature set. A constrained single-process or active/standby profile can be operated with trusted publishers, durable compatible stores, stable identity, MQTT Quality of Service (QoS) 1 or 2, idempotent consumers, required telemetry, and tested failover timing. Coordinated cluster rollout remains outside that profile.
The implementation has sound foundations: manual MQTT QoS 1/2 settlement, bounded ingress, durable shared outbox support, lease fencing, restart-monotonic fences for durable pairings, explicit health levels, and a proven compressed owner-death failover path. Since the first audit, chunks 1–4 of `PROD_READY_PLAN.md` closed the identity-trust, URL-alias, binary-correlation, egress-limit, proxy, and accepted-tradeoff findings (`cf86968f`, `84939bf5`, `f0c9685c`, `b781f741`). Confirmed defects still permit loss, ordering violations, stalled delivery, false service-level objectives (SLOs), unbounded lifecycle waits, and permanent mixed cluster generations, and the second pass found seven new HIGH defects: a reconnect-window ack wedge in the MQTT router, SIGTERM cancelling in-flight work before drain in both shipped binaries, cancellation feeding the poison gate, a lease re-seized and held to TTL after session failure, DynamoDB claim ordering and mid-batch claim discard, and a dead runtime retained as current after a failed stop.

## Verified strengths
- MQTT QoS 1/2 acknowledgement waits for runtime settlement. Receive Maximum, bounded queues, count limits, and memory admission provide coherent backpressure for accepted packets. Pending-byte refusal is confined to QoS 0.
- Poison handling chooses bounded, metered loss over infinite persistent-session replay. Direct hold waits for destination acceptance. Durable shared outbox supports persist-before-acknowledgement, fencing, reclaim, and takeover.
- Lease owners fail closed at their local deadline. Managed-subscription changes use durable history and fail-closed reconciliation. Reload builds a replacement runtime instead of mutating the live runtime.
- Readiness has explicit semantic levels. Published modules have no release-blocking `replace` directives. The pinned Paho-version tripwire rejects unsupported software development kit (SDK) drift.

## Verified non-findings
- `AllowUnfenced` does not bypass outbox fencing; it is a validation escape for direct-hold shared consumers. Built-in managers and drainers derive partition and lease identity from the same session ID, so they do not create separate fencing-version spaces.
- `on_expired: dlq` records are not destroyed by bulk expiry. Bulk expiry runs for drop policy; DLQ expiry claims, writes, and completes each record under fencing.
- DLQ redrive injects before delete and rejects a runtime without the safe injection seam. The residual risk is duplication, not delete-first loss.

## Message delivery, loss, duplicate, and timeout matrix
There is no exactly-once mode. The strongest supported contract is durable at-least-once delivery with downstream idempotency and possible duplicates.
| Path or event | Settlement behavior | Loss or duplicate outcome | Evidence or signal |
|---|---|---|---|
| MQTT QoS 1/2 `direct_hold`; destination and source acknowledgement succeed | Source held until target acceptance | Delivered once in normal path | Route settlement and manual MQTT acknowledgement |
| Same path; target succeeds but process dies or source acknowledgement fails | Broker redelivers | Duplicate target send possible | Downstream idempotency required |
| Outbound packet exists only in Paho memory at process death | MQTT in-flight state disappears | No protocol exactly-once; source redelivery or durable outbox compensates | Paho egress is volatile |
| QoS 1/2 durable `shared_outbox` with `ack_after: outbox_persist` | Record persists before PUBACK | Crash-surviving at-least-once | Outbox metrics |
| Outbox send succeeds but `Complete` fails/fence changes | Record retries or reclaims | Duplicate send possible | `OutboxDuplicateRisk` |
| Shared outbox uses memory | Acknowledgement can precede process loss of record | Restart loss | Development-only store |
| QoS 0 under queue, shutdown, or emit pressure | No reliable backpressure/redelivery | Best-effort loss | Most queue drops use `MQTTRouterDropped`; emit rejection has no metric |
| Covered QoS 0 byte refusal | Drop without reservation release | Capacity drains until restart | Drop metered; leak is not |
| Post-grace orphan topic | Acknowledge/drop and concrete unsubscribe | Deliberate loss; wildcard can survive | Unmatched-drop metric/log |
| Packet exceeds local policy after decode | Acknowledge/drop to stop poison replay | Deliberate terminal loss | `MQTTIngressPoisonDropped` |
| Malformed packet cannot decode safely | Session fails closed | Unsettled QoS can redeliver; compatibility outage possible | Terminal recovery |
| Transient processor/resolver/send/persist failure with stable trusted identity | Bounded retry | At-least-once; eventual DLQ/drop | Retry/DLQ/drop metrics |
| Same failure without stable identity | Generated ID changes on redelivery | First failure terminal under finite cap | `unstable_identity` poison |
| Spoofed generated marker | **Closed (HIGH-1):** marker stripped at ingress; provenance is adapter-owned | — | `generated_identity_test.go` |
| Reused publisher `mqtt.message-id` | Duplicate treated as success and source acknowledged (by design) | Distinct message lost | `OutboxDuplicateSuppressed{route_id}` (HIGH-8 closed: metered) |
| Binary Correlation Data | **Closed (NEW-HIGH-2):** stable `mqtt-bin:` identity ≤256 B, raw bytes round-tripped | >256 B raw still minted (accepted) | `binary_correlation_identity_test.go` |
| Oversize MQTT metadata | **Closed (NEW-MEDIUM-4):** rejected before packet build | Permanent rejection | `MQTTEgressRejected` |
| Broker Maximum Packet Size exceeded | **Closed (NEW-HIGH-3):** per-generation ceiling enforced before write | Permanent `ErrPayloadTooLarge` | `MQTTEgressRejected` |
| Ordering-key head stranded; later sibling arrives | Claim ignores older sibling | Later row can overtake | No ordering signal |
| Claimed release fails | Work waits for stale/version reclaim | Depth can show zero; direct version-only use can strand | Pending gauge excludes claimed |
| Permanent failure with durable DLQ | DLQ write precedes terminal settlement | Evidence survives; acknowledgement failure can duplicate DLQ | `DLQEntries`, `DLQWriteFailures`, `DLQDepth` |
| Permanent failure with memory DLQ | Source can settle after volatile write | Restart erases evidence | No required volatility acknowledgement |
| Permanent drop policy | Terminal acknowledgement/drop | Intentional loss | `MessagesDropped`; DLQ policy without store is rejected |
| TTL expiry or processor filter | Terminal policy settlement | Intentional expiry/discard | `MessagesExpired`, `MessagesFiltered`, or DLQ |
| Owner death with durable outbox | Successor reclaims under higher fence | No loss found; bounded duplicate possible | Lease version and duplicate-risk metric |
| Memory lease with durable SQLite outbox after restart | Reset token is below persisted fence | Ingress persists while drain wedges | `ErrStaleFencingToken` |
| Settlement recovery while accepted send exceeds five seconds | Recovery ends before normal settlement | Session/runtime restart can repeat | Terminal signals |
| Broker grants lower subscription QoS | Reconcile remains degraded | Weaker guarantee and owner churn | `MQTTQoSDowngraded` |
| Publish arrives between CONNACK and `OnConnectionUp` (persistent/exclusive reconnect or recovery recycle) | Dropped un-acked as stale; ack tracker head blocked | QoS 0 lost; QoS 1/2 ingress wedges until an unrelated disconnect | `MQTTRouterStalePurged` only; unsettled gauges cleared (HIGH-14) |
| Delivery context cancelled mid-flight (SIGTERM, swap, receiver cancel) with generated identity and drop policy / no DLQ store | Poison gate fires; terminal ACK under `settleContext` | Message dropped | `MessagesDropped{unstable_identity}` misattributed (HIGH-16) |
| SIGTERM in `cmd/gobridge` or `gobridge-filebased` | Delivery contexts cancelled before drain; 5 s watcher `Stop` may win | Duplicates on every restart; drain budget not honoured | None (HIGH-15) |
| DynamoDB `Claim` fails mid-batch | Already-claimed rows stranded to stale window; replay budget charged | Overtaking; DLQ without send after budget | Depth reads low; `OutboxRecordFailures` (HIGH-19) |
| DynamoDB `ClaimIndex` lag | Younger sibling claimed first | Ordering violation | None (HIGH-18) |
| DLQ redrive of adapter-identified entry, first transient failure, drop policy | Dropped; admin deletes entry | Message and evidence lost | `DLQRedrives` counts success (MEDIUM-21) |
| Persistent/exclusive reconnect returns `SessionPresent=false` | Accepted silently | Offline QoS 1/2 backlog gone | None (MEDIUM-20) |
Minimum loss-sensitive profile: QoS 1/2; unique redelivery-stable identity scoped to an authenticated producer; durable `shared_outbox`; `ack_after: outbox_persist`; SQLite for one process or DynamoDB for a cluster; durable DLQ and alarms; idempotent consumers.
### Reporting boundary
Metrics, events, hooks, and audit publishers are operational signals, not a durable ledger. They can be best-effort or Noop. Conservation needs separate filtered and expired terms. Production requires non-Noop telemetry and alarms; per-message accountability requires a durable terminal-outcome ledger.

## Failover and recovery timing
Conservative owner-death budget:
```text
lease_ttl + 2 * maximum_jittered_acquire_poll
+ (1 + ceil(lease_ttl / minimum_jittered_acquire_poll)) * renew_call_timeout
+ complete MQTT post-takeover activation + startup_allowance
```
MQTT activation is `2 * connect_timeout + 4 * reconcile_timeout + 2 * unmatched_grace`; shipped 30-second values make that term 240 seconds.
| Failure mode or profile | Conservative contract | Verdict |
|---|---:|---|
| Cluster default: 45 s lease, 5 s poll, 3 s call, default activation | About **336.5 s** | No 30–60 s worst-case contract; omission of `failover_slo` logs but does not reject |
| Standalone default: 360 s lease, derived 5 s poll, 5 s call, default activation | About **1,097.5 s** | TTL alone omits observation, calls, polling, and activation |
| Tuned profile: 15 s lease, 2 s poll, 1 s call, 3/2/2 s MQTT | About **49 s** | Can satisfy declared 60 s owner/process-death objective with admission |
| Separate-process test: compressed 5 s lease | **25 s** ceiling | Passed locally; proves mechanics, not defaults |
| Graceful release | No TTL wait | Polling and activation remain |
| `SIGKILL` or node loss | Full observation, polling, activation | Proven on compressed timing |
| Node-local broker outage, default | **Unbounded** | Owner keeps renewing |
| Broker outage with threshold | Threshold + release + polling + activation | Admission omits threshold |
| MQTT settlement recovery | Fixed **5 s** drain; 30 s cooldown can precede another attempt | Unsafe against 30–35 s settlement ceiling |
| Rollout coordinator crash | 30 s lease plus delay/polling | Near/above 60 s; black-holed call is unbounded |
| Session failure on the deferred-connect path (default) | Release, restart, re-seize, terminal without release | **≥ lease_ttl + poll + activation** instead of one poll (HIGH-17) |
| Derived timings with large `max_renew_fails` | Renew/poll clamp to 1 ms | Store storm accepted by validation (MEDIUM-24) |
Owner/process/node death can meet 30–60 seconds only with a tuned, declared, admitted, measured profile. Defaults do not. Broker-only default does not fail over; enabled policy lacks trustworthy admission; rollout failure remains unsafe until calls and deadman are independently bounded.

## Runtime and cluster reconfiguration assessment
### Single process
Useful foundations: resolve/validate before build; exclusive identity selects prepare/commit; old runtime remains until candidate preparation; failed candidate attempts old-runtime restore; desired/running version and last error are tracked.
Current limits: every change restarts every session; HTTP and shutdown budgets remain boot-configured; invalid broker-health/backoff can commit before failure; log level mutates before acceptance and ignores unknowns; plan and late-start cleanup gaps remain; apply can outlive HTTP response; settlement recovery can terminalize before bounded send completion.
### Cluster
The protocol has frozen membership epoch, digest agreement, all-member acknowledgement before commit, fenced coordinator election, timeout/Nack abort, optional confirm window, and durable artifact.
It is not production-ready: CDK prerequisites are absent; fingerprint rejects real changes; remote calls can stop progress/deadman; post-commit apply can diverge; artifact/revert failures latch; baseline is not seeded; voter lacks blueprint validation; health omits applied/converged/fresh state. Use controlled whole-cohort replacement with orchestration rollback. Do not call cluster commit cohort-atomic.

## Container and orchestration assessment
Published v0.3.3 digest: `ghcr.io/mariotoffia/gobridge@sha256:e4dbdb80b3d7062b6fe5ac0aa5a921c1e415bbe593979dc35ee0f51714677f7c`. A guarded `latest` also exists; production should pin the digest.
**ECS/AWS:** The stock image and CDK provide file-based process, health endpoints, EFS, SSM, DynamoDB, CloudWatch, and Fargate definitions. Coordinated rollout is blocked; replacement-required changes cannot use overlapping worker deployment.
**Docker on AWS:** Viable with bootstrap, SSM, DynamoDB, network, restart, and termination-grace setup.
**Kubernetes/non-AWS Docker:** Not turnkey. The stock image builds AWS clients unconditionally. Operators need a composition root, binary/image, secrets, durable stores, manifests, probes, alarms, and runbooks. The generic template probes an unconfigured listener and sets an unused key. Core library is portable; production artifact is not.
Twelve-factor support is limited to bootstrap JSON/file variables without YAML environment interpolation. Mounted config works; this is a developer-experience gap.
Required orchestration: use `/api/v1/monitor/live` for restarts and `/api/v1/monitor/ready?level=full` or `subscribed` for traffic; keep admin reachable for not-ready tasks; auto-restart terminal Paho sessions; set termination grace above total process shutdown; persist outbox/DLQ outside container; never use per-task durable MQTT identity for clustered exclusive sessions; force whole-cohort replacement for incompatible identity/store changes.
